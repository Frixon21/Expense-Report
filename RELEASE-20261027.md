# Expense Report — quality-of-life release candidate, 2026-10-27

Standalone application only. The separate Odoo development fork is unchanged. No publication or TrueNAS deployment was performed for this release.

## Changes

- Light, Dark and System appearance, remembered on this browser. System follows operating-system changes. Browser print output remains light; existing generated PDF reports remain unchanged.
- Authenticated form preferences: last saved expense category/payment method and mileage destination. New entries use today's local date, clear amounts, and retain the existing suggested starting odometer.
- Duplicate expense/trip actions create new IDs and timestamps. Expense amount and mileage end/costs are cleared. Confirm the new date and amount/distance/costs before saving. Changing a field resets confirmation. Receipts and payroll processing/payment status are never copied.
- New, editing and duplicate forms recover unfinished text after refresh, back navigation or closing the page. Recovery is explicit; editing recovery checks that the source record still exists and is editable. Duplicate recovery requires fresh confirmation. Receipt files are not cached in drafts and must be chosen again; an editing draft retains the receipt already saved on its original record.
- Drafts/preferences are separated by authenticated account and module. Drafts expire after 30 days and are cleared on successful save, cancel, explicit discard or confirmed sign-out. Draft text is ordinary local browser storage, not encrypted server storage or a cross-device backup; sign out on shared devices. Disabled/full browser storage produces a warning while keeping form input usable.
- Lazy image thumbnails, image decode checks, empty/oversize/type errors, malformed/password-protected PDF rejection, viewer rotation and editable attachment rotation. Attachment rotation saves a PNG replacement on the next normal expense save. Viewer rotation is temporary and leaves the downloaded original unchanged. Images over 40 million decoded pixels are rejected to bound browser memory use.
- Existing owner-filtered record history now shows actual recorded status transitions, dates, actors, record names and reasons. Workflow remains Submitted, Processed, Paid and Voided, including reversals; there is no invented approval/rejection state. Records predating history are not assigned fabricated timestamps.

No database schema, BTAuth/JWT checks, roles, same-origin rules, HTTP transport settings, persistent volumes or dependency versions changed. Browser validation improves the normal upload flow; it is not a server-side malware scanner or OCR.
